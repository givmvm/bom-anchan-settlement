# ボム & あんちゃん 精算

日々の支出を記録して、ボムとあんちゃんの負担額と過不足を計算する静的Webアプリです。

GitHub Pagesでそのまま公開できます。

## 2026-10-19 同期修正（v14）

- 移行前のlocalStorageを `couple-ledger-original-v13:<room>` にそのまま保持。
- 各支出にUUIDと論理リビジョンを付け、削除も墓標として共有する。
- 古い連番IDの衝突は内容別に保持。同一IDで内容が異なる既存記録は、重複の可能性を画面に表示する。
- Supabaseを読み、端末の記録と統合した後、取得時の `updated_at` と一致する場合だけPATCH。競合時は再取得して再試行する。
- 通信中の追加編集、通信失敗、再起動後も端末状態を保持。置換される支出の旧版も `couple-ledger-conflict-v2:*` に保持。
- 「バックアップを書き出す」は元データ・現在の一覧・各共有コードの状態・競合の旧版をJSONで保存する。公開リポジトリへ支出データを入れない。
- 公開用キーは `apikey` ヘッダーで送信。外部API通信をService Workerの対象から除外。

検証: `node --test tests/sync.test.cjs`（実際のDBへは接続せず、複数端末と競合を再現）。

### 復旧時の注意

Supabaseプロジェクト `cbgwabyxohnsiaucfwmq` は調査時点でDNS解決不可。管理画面で状態を確認し、休止中なら既存プロジェクトを復元する。既存テーブルの削除・再作成やデータ初期化は行わない。

両端末ともv14が読み込まれたことを「バックアップを書き出す」ボタンで確認し、バックアップを保存してから同期する。旧v13を開いたまま使うと全件上書きが再発し得るため、両方でアプリを閉じて開き直す。アプリ削除やSafariのデータ消去は不要。

同じ支出が同時編集された場合はリビジョン順で一覧表示を決定し、置換された内容をバックアップ内に保持する。端末ごとの既存データが食い違う場合は自動判断で捨てずに両方保持するため、一覧を確認する。
